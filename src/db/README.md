## 🏗️ Структура та Призначення

Ця папка є **Single Source of Truth (SSOT)** для структури бази даних.
Усі таблиці, індекси, функції та тригери визначаються ТУТ. Якщо чогось немає в цих файлах — цього не повинно бути в базі.

### 🌳 Дерево Файлів

```text
src/db/
├── 🐍 init_db.py               # Головний скрипт ініціалізації (Python)
├── 📜 schema.sql               # Базова схема (Postgres extensions, enums)
├── 📜 users.sql                # Таблиця користувачів та їх метаданих
├── 📜 messages.sql             # Таблиця історії повідомлень
├── 📜 agent_sessions.sql       # Таблиця сесій LangGraph
├── 📜 memory_schema.sql        # Схема для системи пам'яті (Facts, Vectors)
├── 📜 webhook_dedupe_schema.sql # Таблиця дедуплікації вебхуків
├── 📜 fix_orders_unique.sql    # Специфічні фікси (Legacy)
└── 📂 migrations/              # Хронологія змін БД
    ├── 20241205_create_llm_traces.sql
    ├── 20251229_drop_orders.sql
    └── ...
```

## 🧩 Опис Компонентів

### 1. 🐍 `init_db.py` (The Controller)
Це скрипт-оркестратор. Він:
*   Підключається до БД (використовуючи змінні з `.env`).
*   Послідовно виконує SQL-файли.
*   Є **ідемпотентним** (безпечно запускати багато разів — він створює таблиці `IF NOT EXISTS`).

### 2. 📜 Core SQL Files (Скелет)
*   **`schema.sql`**: Активує розширення (`pgvector`, `uuid-ossp`) та створює загальні типи.
*   **`users.sql`**: Зберігає профілі клієнтів (`user_id`, `tags`, `variables`).
*   **`messages.sql`**: Вся історія чатів. Критично для контексту агента.
*   **`memory_schema.sql`**: Описує таблицю `mirt_memories` з векторним пошуком (`embedding vector(1536)`).

### 3. 📂 `migrations/` (Історія Змін)
Містить **незмінні** (immutable) SQL-патчі.
*   Формат імені: `YYYYMMDD_description.sql`.
*   Призначення: Вносити зміни в існуючу базу (ALTER TABLE, CREATE INDEX) без втрати даних.

## 🛡️ Протоколи Безпеки (Safety Protocols)

### 👨‍💻 Для Розробників (Humans)
*   **Створення таблиці:** Додайте новий `.sql` файл в корінь `src/db` І додайте його виклик в `src/db/init_db.py`.
*   **Зміна таблиці:** Створіть новий файл в `src/db/migrations/` (наприклад, `20260112_add_email_column.sql`). **Ніколи не змінюйте старі файли.**
*   **Бекап:** Перед будь-якими ручними маніпуляціями робіть `pg_dump`.

### 🤖 Для AI Агентів (Agents)
*   **READ-ONLY:** Ви можете читати ці файли, щоб зрозуміти структуру даних.
*   **NO DELETE:** Видалення будь-якого файлу з цієї папки суворо заборонено.
*   **MODIFY:** Модифікація дозволена **тільки** додаванням нових міграцій або дописуванням в кінець `schema.sql` (якщо це нова сутність).

> 🔐 **Цілісність даних — пріоритет №1.**
> Код можна переписати. Втрачену базу даних відновити значно важче.
