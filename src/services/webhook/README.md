# 🎣 Webhook Service — Фільтр Дублікатів

> **Роль:** "Bouncer" (Вишибала)
> **Відповідальність:** Гарантує, що ми не обробляємо одну й ту ж подію двічі.

Це критично важливо для інтеграції з **Instagram/Meta** та **ManyChat**.

---

## 🔗 Де використовується? (Usage)

Цей сервіс стоїть на "передовій" вхідного трафіку:

| Файл | Роль |
| :--- | :--- |
| **`src/server/routers/webhooks_manychat.py`** | **CRITICAL PROTECTION**. Перевіряє кожен вхідний запит від ManyChat перед передачею в `ConversationHandler`. |

Тільки тут. І це правильно, бо це специфічна проблема Webhook-інтеграцій.

---

## ⛔ Проблема (Why we need this?)

Платформи на кшталт Meta мають policy "At least once delivery".
Це означає, що якщо наш сервер відповів трохи повільніше (або просто так), Meta надішле **той самий вебхук ще раз**.

**Без цього сервісу:**
1.  Клієнт пише "Ціна?".
2.  Бот отримує 2 вебхуки.
3.  Бот відповідає двічі: "100 грн", "100 грн".
4.  Клієнт думає, що бот зламався.

---

## 🛠️ Як це працює? (`webhook_dedupe.py`)

Ми використовуємо **PostgreSQL** (таблиця `webhook_dedupe`) як атомарне сховище ключів.

### Логіка ID:
1.  **Якщо є `message_id`:** Використовуємо його. Це ідеальний унікальний ключ.
2.  **Fallback (хеш):** Якщо ID немає, ми генеруємо хеш:
    `SHA256(user_id + text + image_url + 5_min_bucket)`

### Процес:
1.  Приходить вебхук.
2.  Ми намагаємось зробити `INSERT` ключа в базу.
3.  Якщо успішно -> Обробляємо.
4.  Якщо помилка `Duplicate Key` -> **Ігноруємо (200 OK)**. Бот навіть не запускається.

## 🏗️ Архітектура
Цей сервіс живе "на вході" (в API Routers), до запуску важких агентів.

```python
# src/server/routers/webhooks_manychat.py

dedupe = WebhookDedupeStore()
if await dedupe.check_and_mark_async(user_id=uid, message_id=mid):
    return Response(status_code=200) # Вже бачили, ігноруємо
```

Це економить ресурси (не запускаємо LangGraph дарма) і рятує UX.
