# Аналіз підходу: Keywords vs LLM vs Snippets

## Поточний підхід: Keywords-Only

### ✅ Переваги:
1. **Швидкість** - немає затримок від LLM API
2. **Вартість** - безкоштовно (немає витрат на токени)
3. **Детермінованість** - завжди однакова поведінка
4. **Простота** - легко тестувати та підтримувати

### ❌ Недоліки:
1. **Обмежена покриття** - не всі edge cases
2. **Залежність від тексту** - якщо текст порожній → консервативний підхід
3. **Не розуміє контекст** - тільки патерни, не семантика

## Альтернатива: LLM в промпті (як би зробив топ-сеньор)

### ✅ Переваги:
1. **Розуміння контексту** - LLM розуміє семантику
2. **Гнучкість** - покриває всі edge cases
3. **Адаптивність** - працює з новими формулюваннями

### ❌ Недоліки:
1. **Швидкість** - затримка 1-3 секунди
2. **Вартість** - ~$0.001-0.01 за запит
3. **Непередбачуваність** - може давати різні відповіді
4. **Складність тестування** - важче тестувати non-deterministic поведінку

## Гібридний підхід (ТОП-СЕНЬОР рівень)

### Архітектура 3-рівневої системи:

```
┌─────────────────────────────────────────┐
│  User Message: "А можна ще додати"     │
└─────────────────────────────────────────┘
              ↓
┌─────────────────────────────────────────┐
│  LEVEL 1: Snippets (0ms, $0)           │
│  - Швидкі, детерміновані відповіді      │
│  - Типові сценарії                      │
└─────────────────────────────────────────┘
              ↓ (не знайдено)
┌─────────────────────────────────────────┐
│  LEVEL 2: Keywords Rules (1ms, $0)     │
│  - detect_product_addition_intent()    │
│  - detect_payment_proof()               │
│  - Швидко, але обмежено                 │
└─────────────────────────────────────────┘
              ↓ (неоднозначно)
┌─────────────────────────────────────────┐
│  LEVEL 3: LLM Fallback (1-3s, $0.001) │
│  - Складні випадки                      │
│  - Контекстна аналітика                 │
└─────────────────────────────────────────┘
```

### Реалізація для product addition:

```python
def detect_product_addition_smart(
    user_text: str,
    has_image: bool,
    state: dict[str, Any],
) -> bool:
    """
    Smart detection with 3-level fallback.
    """
    # LEVEL 1: Snippets (якщо є готовий snippet)
    snippet = maybe_apply_snippet_policy(state, user_text=user_text)
    if snippet and snippet.get("intent") == "PRODUCT_ADDITION":
        return True
    
    # LEVEL 2: Keywords (швидка перевірка)
    if detect_product_addition_intent(user_text):
        return True
    
    # LEVEL 3: LLM Fallback (тільки якщо неоднозначно)
    if not user_text or len(user_text) < 3:
        # Порожній текст → консервативний підхід
        return False
    
    # Якщо keywords не спрацювали, але є зображення + короткий текст
    # → використати LLM для класифікації
    if has_image and len(user_text) < 20:
        return _llm_classify_product_addition(user_text, state)
    
    return False
```
